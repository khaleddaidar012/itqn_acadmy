# الدفع الدولي عبر Paymob

## ما تم تجهيزه

- الباقات الدولية تستخدم صفحة Paymob المستضافة بدل PayPal/التحويل اليدوي. الدفع المصري لم يتغير.
- الدفع من حساب الطالب فقط، بما فيه الحساب الذي ينتظر التفعيل. يحدد الخادم بلد الاتصال والباقة والسعر، ولا يقبل مبلغًا يرسله المتصفح.
- باقات الإخوة: 64$ للأخوين و90$ لثلاثة إخوة. الباقة الفصلية 28$ شهريًا تحصل 84$ مرة واحدة. جميع العمليات دفعة واحدة؛ لا يوجد تجديد تلقائي أو حفظ بطاقة.
- `/api/payments`: تهيئة الدفع وعرض السجل الخاص بصاحب الحساب. الأدمن يرى سجل الطلاب؛ المعلم والمسؤول لا يحصلان تلقائيًا على بيانات مالية.
- `/api/payments/paymob/webhook`: استقبال Transaction callbacks، والتحقق من HMAC-SHA512 والمبلغ والعملة ورقم أمر Paymob وIntegration ID.
- إعادة المتصفح من Paymob لا تغير حالة الطلب. صفحة `/ar/payment-result?order=...` ونسختها الإنجليزية تقرآن حالة الخادم فقط.
- الإشعارات المتكررة لا تنشئ استحقاقًا جديدًا. تحديث الحالة وسجل الحدث في معاملة قاعدة بيانات واحدة. إشعارات استرداد/إلغاء مبلغ مدفوع أو نجاح عمليتين لنفس الأمر تحول الطلب إلى مراجعة مالية.
- لا يتم تفعيل الطالب تلقائيًا. الدفع الحقيقي المؤكد يظهر في طلب التسجيل، والإدارة تؤكد الاشتراك بعد مراجعة الباقة والطلاب. عمليات Test موسومة بوضوح ولا تعتبر سدادًا حقيقيًا.
- لا نحفظ تفاصيل البطاقة أو جسم إشعار البوابة. الحقول المحفوظة: مرجع الطلب، الباقة، المبلغ، حالة العملية وأرقام البوابة؛ لا تحفظ المفاتيح أو client_secret في قاعدة البيانات.

## متطلبات التشغيل الفعلي — لم تكتمل بعد

1. حساب تاجر Paymob مصر معتمد لنشاط الأكاديمية، مع تفعيل البطاقات الدولية **وعملة USD**. وجود حساب أو قبول بطاقة أجنبية لا يعني اعتماد التسوية بالدولار. أكد العملة والتسوية مع Paymob أولًا. التكامل لا يحول السعر إلى جنيه تلقائيًا.
2. Secret Key وPublic Key وHMAC Secret وIntegration IDs لبطاقات USD، من نفس الحساب ونفس وضع Test أوLive.
3. نطاق HTTPS عام ثابت للموقع على Cloudflare مع قاعدة D1 حقيقية. localhost لا يستقبل إشعارات Paymob من الإنترنت.
4. نسخ القيم من `.local/paymob-settings.env` إلى `.env.local` للتطوير فقط، أو إعداد القيم كمتغيرات وأسرار Cloudflare. الملف المحلي لا يتم تحميله تلقائيًا ولا يرفع إلى Git. لا ترسل المفاتيح في الشات.
5. تفعيل `PAYMOB_USD_ENABLED=1` فقط بعد التأكد من دعم USD. القيم الناقصة أو المتعارضة تمنع بدء الدفع وتظهر رسالة أنه قيد التفعيل.

| المتغير | القيمة المطلوبة |
| --- | --- |
| PAYMOB_MODE | test أولًا، ثم live بعد اختبار واعتماد الحساب |
| PAYMOB_SECRET_KEY | sk_test_... أو sk_live_...؛ سر على الخادم |
| PAYMOB_PUBLIC_KEY | pk_test_... أو pk_live_...؛ من نفس الوضع |
| PAYMOB_HMAC_SECRET | سر توقيع Transaction callbacks |
| PAYMOB_USD_INTEGRATION_IDS | أرقام التكامل لبطاقات USD، مفصولة بفاصلة بدون مسافات |
| PAYMOB_USD_ENABLED | 0 افتراضيًا، أو1 بعد التفعيل |
| ITQAN_APP_URL | أصل الموقع العام فقط، مثل https://academy.example، بدون مسار |

في Cloudflare ضع المفاتيح الحساسة عبر `wrangler secret put`، دون وضعها في wrangler.jsonc أو NEXT_PUBLIC. طبق ترحيل `0005_payments.sql` مع بقية الترحيلات قبل التشغيل. لا تفتح حسابات دفع أو تقبل عقودًا تلقائيًا من الكود.

## اختبار قبل Live

- `npm run test:payments`: اختبار محلي بقاعدة SQLite ومزود Paymob محاكى؛ لا يتصل ببوابة حقيقية ولا يخصم أموالًا.
- `npm run test:system` و`npm run test:system:d1`: تحقق من توافق النظام وقاعدة البيانات.
- `npx tsc --noEmit`: تحقق الأنواع.
- بعد توفير الحساب والنطاق، نفذ Sandbox حقيقي ببطاقة اختبار Paymob: نجاح، رفض، 3DS، إغلاق نافذة الدفع، تكرار إشعار، طلب غير مطابق للبلد، باقة الإخوة، والـ84$ الفصلية.
- تحقق من وصول POST الفعلي إلى webhook وتطابق توقيع كل حقل مع حساب التاجر. القيم الناقصة أو null في حقول التوقيع تفشل عمدًا؛ لا تعطل التحقق للتغلب على الاختلاف. التكامل الحالي مهيأ لبطاقات الدفع فقط، وليس لإشعارات Token أو المحافظ.
- افتح نتيجة الدفع بحساب طالب آخر وتحقق من عدم كشف الطلب. راجع ظهور طلب مدفوع لدى الأدمن، وبقاء التفعيل بقرار الإدارة.
- نجاح الاختبارات المحاكاة لا يؤكد اعتماد حساب التاجر أو إمكانية التحصيل الحقيقي. لم يُجر اختبار Sandbox حقيقي أو عملية Live لعدم وجود مفاتيح حساب التاجر والنطاق العام.
