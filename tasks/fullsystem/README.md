## مراحل التنفيذ
- [x] 01 — حسابات آمنة: دخول موحد، تسجيل الطلاب، إنشاء أول مدير من إعداد الخادم، جلسات وصلاحيات من الخادم؛ يلزم ضبط بيانات المدير لتفعيل حسابه الفعلي.
- [x] 02 — إدارة المعلمين: إنشاء حسابات، أجر الساعة USD/EGP، منح صلاحية إدارة الجداول.
- [x] 03 — الطلاب والمواد: حفظ، تجويد، عربية؛ ربط ولي الأمر بأبنائه بواسطة الإدارة.
- [x] 04 — الجدول الأسبوعي: تعيين المعلم والطالب والمادة والموعد والمدة ومنع التعارض؛ تكرار أسبوعي حتى 12 أسبوعًا.
- [x] 05 — سجل الحصص: حضور، غياب، تأجيل مع موعد جديد، إلغاء مسموح، إلغاء متأخر محسوب.
- [x] 06 — حضور المعلم: توقيت دخول من الخادم، حساب الدقائق المتأخرة والمستحقات الشهرية، تثبيت الأجر عند إنشاء الحصة.
- [x] 07 — التقدم: توثيق المعلم للصفحات المحفوظة من أصل 604 ونسبة تقدم الطالب.
- [x] 08 — لوحات حسب الدور: الإدارة والمعلم والطالب وولي الأمر، جدول أسبوعي وأداء المعلمين.
- [ ] 09 — الاجتماعات: المزود المختار Zoom؛ يلزم ربط حساب الأكاديمية لتوثيق الدخول وإغلاق الاجتماع من الخادم.
- [ ] 10 — الإنتاج: قاعدة بيانات دائمة ونسخ احتياطية، استعادة كلمة المرور، اختبارات، نشر ومراقبة.

## قرارات النسخة الأولى
واجهة عربية متجاوبة مع هوية الموقع. الاستضافة المختارة Cloudflare Workers وقاعدة D1؛ SQLite المحلية للتطوير على Node.js 24. راجع CLOUDFLARE.md للإعداد. حفظ مواعيد UTC وعرض بتوقيت القاهرة. مهلة الإلغاء الافتراضية 12 ساعة وقابلة للتعديل في متغير البيئة. المستحق = أجر الساعة × دقائق الحضور داخل فترة الحصة ÷ 60؛ لا يجوز جمع الدولار والجنيه في إجمالي واحد. هذا توصيف حسابي، وليس فتوى. حساب الطالب وحده يُنشأ من التسجيل العام. ولي الأمر يُنشأ ويربط بالطالب من الإدارة.

## تشغيل
راجع SETUP.md. لا يتم إنشاء حسابات تجريبية أو كلمات مرور عامة. المهام لا تعتبر مكتملة قبل التحقق؛ تكامل الاجتماعات والنشر لهما إعدادات مستقلة.

## تعريف القبول
1. التسجيل العام لا يرفع صلاحيات المستخدم حتى عند تغيير طلب الشبكة.
2. الجلسة محفوظة في cookie محمية HttpOnly، وتبطل عند الخروج؛ كلمات المرور hashed باستخدام scrypt.
3. المعلم لا يرى طلاب غير معينين له، وولي الأمر لا يرى غير أبنائه؛ مسؤول الجداول لا يرى أجور باقي المعلمين.
4. الموعد المتداخل مرفوض للطالب والمعلم؛ التأجيل يحتفظ بالحصة القديمة وينشئ بديلًا داخل transaction.
5. بداية ونهاية الحضور من وقت الخادم؛ لا يحتسب قبل بداية الحصة أو بعد نهايتها.
6. تأخير عشر دقائق يساوي أجر الساعة × 10 ÷ 60 مهما كانت مدة الحصة.
7. تقدم الحفظ يسجل فقط من معلم حصة حفظ حضرها، ويتراوح بين 0 و604 صفحة.
8. تغيير الأجر لا يغير الحصص القديمة، ولا تجمع عملات مختلفة.

## المتبقي قبل الإطلاق
ربط Zoom وإغلاق الاجتماع فعليًا، ربط حساب Cloudflare وإنشاء قاعدة D1 السحابية وتفعيل المدير عليها (حسابه المحلي تم إنشاؤه)، استعادة كلمات المرور عبر البريد، مراجعة سياسة الاحتساب مع الإدارة، سجل تدقيق إداري، نسخ احتياطية تلقائية، وإدارة مدفوعات الطلاب. تغيير كلمة المرور من الحساب متاح. اللغة الإنجليزية للنظام الداخلي تحتاج ترجمة منفصلة؛ صفحات الموقع الأصلية تظل ثنائية اللغة.

## التحقق
نجحت اختبارات API باستخدام قاعدة مؤقتة: أدوار الحسابات، عزل الطلاب، ربط ولي الأمر، رفض تعارض الجداول، rollback الجدولة المتكررة عند التعارض، رفض الدخول من معلم آخر أو خارج الموعد، الحضور، تقدم الحفظ، الإلغاء المسموح، تثبيت أجر الحصص، إخفاء أجور الآخرين عن مسؤول الجداول، تغيير كلمة المرور وإبطال الجلسات، والخروج. نجحت اختبارات احتساب دقائق التأخير في حصة 60/30 دقيقة وحدود نهاية الحصة والمغادرة المبكرة. فحص TypeScript والبناء نجحا. تكامل الاجتماعات والإنتاج غير مختبرين لأنهما لم يُضبطا بعد.

تحقق تشغيل نسخة الإنتاج محليًا: `/ar/login` و`/ar/register` يرجعان 200، ولوحة التحكم بدون جلسة ترجع 307 إلى صفحة الدخول، وAPI بدون جلسة يرجع 401. راجعت صفحة الدخول والتسجيل وروابطهما في قائمة الهاتف من المتصفح؛ لم تختبر جميع لوحات الأدوار بصريًا، وتم التحقق من عملياتها عبر API.

بعد اختيار Cloudflare: أضيفت طبقة async لقاعدة البيانات مع binding D1 وعمليات batch ذرية وtrigger يمنع تداخل الحصص حتى مع الطلبات المتزامنة. نجحت `npm run test:system` و`npm run test:system:d1` وTypeScript؛ اختبارات D1 تعمل على محاكاة Cloudflare حقيقية محليًا ببيانات مؤقتة، وليست قاعدة سحابية. راجع CLOUDFLARE.md قبل النشر، فمعرّف القاعدة الموجود تجريبي وأوامر النشر ترفضه.

نجح أيضًا `npm run build:cloudflare` و`npm run test:system:worker`، حيث تم اختبار العمليات داخل Workers + D1، بما فيها منع الموعد المتداخل مع طلبين متزامنين والتأجيل الذري. يلزم بناء حزمة OpenNext قبل اختبار Workers. قاعدة البيانات السحابية وربط الحساب والنشر لم تنفّذ بعد.
